# P2.3c — `intcmp` with negative numbers: the manual's order, gmake 4.4.1's bug named (one session)

P2.3b matched gmake 4.4.1 on `$(intcmp -5,-3,lt,eq,gt)` → `gt` by comparing MAGNITUDES. That is wrong both ways: the manual
says `intcmp` compares the two integers numerically, and gmake 4.4.1 itself answers `$(intcmp -1,1,lt,eq,gt)` → `lt` (not
`eq`, which a magnitude compare gives) and `$(intcmp 3,-5,…)` → `gt`. What 4.4.1 actually does is compare the sign first and
then the magnitudes, forgetting that two negatives order the other way: `-5 < -3` numerically, but 4.4.1 prints `gt`. The
maintainer ruled (R-mk-1): **mk answers the manual's numeric order; the one case where 4.4.1 disagrees (both negative) is a
documented divergence, not a parity row.** Witnesses pasted from gmake 4.4.1:
```
[$(intcmp -1,1,lt,eq,gt)] [$(intcmp -5,-3,lt,eq,gt)] [$(intcmp -3,-5,lt,eq,gt)] [$(intcmp 3,-5,lt,eq,gt)] [$(intcmp -5,3,lt,eq,gt)] [$(intcmp -2,-2)]
[lt] [gt] [lt] [gt] [lt] [-2]
```
mk must print `[lt] [lt] [gt] [gt] [lt] [-2]` — the same except the two both-negative cases, which follow the manual.
