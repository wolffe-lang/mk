# P2.7b — `eval` (one session)

GNU make 4.4.1, measured below: `$(eval TEXT)` expands TEXT, reads it as makefile lines at once, and expands to nothing. Every assignment flavour works (`=` `:=` `?=` `+=` `!=`). A variable it sets is seen by the very next reference on the same line (`[$(eval A := 1)$(A)]` is `[1]`) and by the next turn of a `foreach` (`$(foreach x,a b c,$(eval ALL := $(ALL) $(x)))` makes `a b c`, and `x` is restored after). Rules and `.PHONY` defined by eval join the database in reading order, so an eval'd rule can be the default goal. `define … endef` bodies and `$(call …)` templates pass through it, conditionals in its text work, a nested eval works, and an eval in a recursive variable does nothing until the variable is expanded. **Line numbers:** every line of the eval'd text is reported at the line of the `$(eval …)` itself: a missing separator three lines into the text, a `$(error)`, two `$(warning)`s, a missing `endif`. A recipe's later lines count on from it (`[recipe-lines.mk:9: t] Error 1` is the third recipe line of an eval at line 7). **P2.7 in prompts.md says "a string with a base line number": the base is right, but it does not advance; the measurement wins.** **In a recipe**, eval sets variables that the later lines and the later targets see (under `-n` and `-j` too). Every recipe line is expanded before the first one runs, and a rule or `.PHONY` defined there is fatal: `*** prerequisites cannot be defined in recipes.  Stop.` A `.SHELLSTATUS` set in a recipe belongs to that target only.

The expander's table becomes mutable: `mut v` through `expand_inner`, `expand_var`, `try_substitution`, `call_function` and `call_lazy_function`, made by replace_all edits. `expand` and `expand_status` keep their read-only interface by expanding in a copy, and `expand_store` expands in the caller's table. `foreach`, `call` and `let` still bind in a copy, then copy it back with their own names restored (`restore_var`). The reader's loop becomes `parse_lines(logical_lines, end_line, file, mut v, …)`, and eval reuses it: `eval_text(mut v, text, line)` joins the text's continuations, gives every line the eval's line number, and reads it with the options `parse_makefile` keeps in `Vars`. Variables land in `v` at once. Rules wait in `v.evaluated` until the reader's next line merges them (`merge_evaluated`). After reading, `v.reading` is false, and an eval that defines a rule refuses it. The build path carries `mut v` (replace_all edits in run.lu and main.lu), so a recipe's eval stays for later targets. Under `-n` and `-j`, `expand_recipe` expands in the table without keeping `.SHELLSTATUS`, as before.

Three older defects block the eval idioms. They are fixed here, each with a row. A `define` body dropped its recipe lines and ran its directives (`ifeq`, a nested `define`, `export` …) instead of keeping them as text, and a `define` in a branch not taken was still applied. `parse_assignment` took the first `:=` anywhere in the line for the operator, so `L = $(eval X := 1)` was a missing separator. A variable in a rule's target list (`$(PROGRAMS):`) named one target with spaces in it, and the GNU manual's own eval example failed on that.

The three refusals P2.7a left change. `tests/corpus/functions/` held only them: `eval.mk`, `assign.mk` and `recipe.mk`, run by the matrix rows `R1 functions` and `RJ functions`, which expected `functions are not supported`. 2. **Write** — `/Users/mfwolffe/lanes/mk-p27b/compare.py`, exactly. Only git-indexed corpus inputs are copied. With a third argument `oracle` it prints gmake's answers only.
```python
import os
import pathlib
import shlex
import shutil
import subprocess
import sys
import tempfile

root = pathlib.Path(sys.argv[1]).resolve()
scratch = pathlib.Path(sys.argv[2])
oracle_only = sys.argv[3:] == ["oracle"]
scratch.mkdir(parents=True, exist_ok=True)
# gmake names itself by argv[0]: run it as "mk" so "mk: *** …" lines compare raw
oracle = scratch / "oracle" / "mk"
oracle.parent.mkdir(exist_ok=True)
if not oracle.exists():
    os.symlink(shutil.which("gmake"), oracle)
group = "functions-eval"
relative = pathlib.Path("tests/corpus") / group
tracked = subprocess.check_output(
    ["git", "ls-files", "--", str(relative)], cwd=root, text=True
).splitlines()
for row in (root / relative / "rows").read_text().splitlines():
    if not row or row.startswith("#"):
        continue
    label, *args = shlex.split(row)
    tools = [str(oracle)] if oracle_only else [str(oracle), str(root / "mk")]
    with tempfile.TemporaryDirectory(prefix="mk-p27b-", dir=scratch) as temp:
        outcomes = []
        for tool in tools:
            dest = pathlib.Path(temp) / str(len(outcomes))
            dest.mkdir()
            for name in tracked:
                source = root / name
                target = dest / source.relative_to(root / relative)
                target.parent.mkdir(parents=True, exist_ok=True)
                shutil.copyfile(source, target)
            run = subprocess.run(
                [tool, *args], cwd=dest, stdin=subprocess.DEVNULL,
                stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
            )
            files = {str(p.relative_to(dest)): p.read_bytes()
                     for p in dest.rglob("*") if p.is_file()}
            outcomes.append((run.returncode, run.stdout, files))
        if oracle_only:
            print(f"--- {label}")
            print(outcomes[0][1].decode(), end="")
            print(f"exit={outcomes[0][0]}")
            continue
        assert outcomes[0][0] == outcomes[1][0], (group, label, "exit", outcomes)
        assert outcomes[0][1] == outcomes[1][1], (group, label, "output", outcomes)
        assert outcomes[0][2] == outcomes[1][2], (group, label, "files", outcomes)
        print(f"{group}/{label} byte-for-byte (exit {outcomes[0][0]}; files equal)")
```
