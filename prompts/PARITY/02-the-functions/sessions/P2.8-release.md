# P2.8 — release 0.4.0 (one session)

Track 02 closes here. Measured at `075d413` on wolf 0.2.36 against GNU make 4.4.1: the 182-probe battery gives `Track 02` 38 of 39 at parity and `Track 02 (!=)` 0 of 1. This session fixes the two that are left, so the judge's battery reads 39 of 39 and 1 of 1; nothing else in the battery moves.

**`is_gmake_function` is dead, and goes with the refusal path.** It lists only `word` and `wordlist`, and `is_text_function` answers both first: the two `functions are not supported` blocks in `expand_inner` run only when `is_text_function` is false, and in `unterminated_message` it is an `||` after `is_text_function`. 40 malformed `word`/`wordlist` calls (no argument, no space, a tab, braces, unterminated, in a recipe, a computed name) never print the refusal. The function goes, with both blocks, `call_function`'s last line (every name `is_text_function` answers has returned before it) and the top-level call's push of a message that does not start with `*** `. After this session every `Refuse` message is gmake's `*** …` line. One older defect sits on the line being changed: an unclosed call with nothing after the function's name (`Y := $(word`, or `$(word ` whose trailing space the reader trims) says `unterminated variable reference`, where gmake names the function. It is fixed here, red rows first, and P2.6c's unit test that asserted the wrong answer turns around.

**`function-assignment-error`** (battery): `Y := $(error HELLO)` printed `mk: Makefile:3: *** HELLO` after the whole parse, because the reader parked every `Refuse` from an assignment in `db.refusals`, a path built for the old by-name refusal. Each of those arms now stops at once with gmake's line, as the top-level call already does, and so does an unclosed call there, so an included file's error names that file. gmake forgives an `-include`d or `sinclude`d file only for being missing, never for an error inside it. mk forgave both, so that arm changes too; otherwise `-include` plus `$(error)` would go from a wrong message to a silent exit 0.

**`define-shell`** (battery, `Track 02 (!=)`): `define X !=` named a variable `X !` and left `X` empty. `parse_define` learns `!=`. `endef` runs the body as one command line: gmake joins the body's lines with spaces (`echo a` then `exit 3` gives `[a exit 3]` with `.SHELLSTATUS` 0), stores the output as a recursive variable, and sets `.SHELLSTATUS`.

**The version line.** wolf 0.2.36 cannot embed the compiler's own version at build time. It has no intrinsic, no std call and no build flag for it, and `wolf --version` at run time reports the wolf on PATH, not the one that built the binary. So `--version` says what its constant is, `mk 0.4.0 (tested with wolf 0.2.36)`. `VERSION` said 0.3.0 while main.lu said 0.3.1. A new test.sh kind, `VR`, checks `--version` against the `VERSION` file and `wolf --version`, so neither can drift again.

**The README.** The *Accepted* table already gives each of the 38 functions an example, and *Refused* has no function row; both were checked, and neither changes. The usage block lacks `-e` and is re-pasted from `./mk --help`. The intro still says "no `include`, no `ifeq`, no functions".
