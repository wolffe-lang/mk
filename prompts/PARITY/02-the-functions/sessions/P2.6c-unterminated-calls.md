unclosed `$(` or `${` whose first word is a function name followed by a space stops with
`FILE:LINE: *** unterminated call to function 'NAME': missing ')'.  Stop.` (`'}'` for a brace), exit 2; anything else
stops with `FILE:LINE: *** unterminated variable reference.  Stop.`. It stops at read time for `:=`, `!=` and a top-level
call; a recursive `=` variable stops where it is expanded, naming its definition line; a recipe stops before any of its
lines runs. Today mk swallows the error in `:=`, `!=` and the top-level call (the raw text reaches `/bin/sh`), and says
"variable reference" for every case. The error row `Unterminated(int)` gains the message: `Unterminated(int, str)`.

```
/// gmake's words for an unclosed `$(` or `${`: a call to a function names the
/// function and the missing close; anything else is a variable reference.
fn unterminated_message(rest: str, close: str) -> str {
    var n = 0
    while n < rest.len && rest[n..n + 1] != " " && rest[n..n + 1] != "\t" {
        n += 1
    }
    let name = rest[0..n]
    let named = is_text_function(name) || is_gmake_function(name) || lazy_function_name(rest).len > 0
    if n < rest.len && named {
        return "unterminated call to function '{name}': missing '{close}'"
    }
    "unterminated variable reference"
}
```
