# P3.1 — the recipe on the rule line, the empty recipe, and the rule with neither (one session)

Track 03 opens here. Every line below was measured at `4e9ba82` on wolf 0.2.36 against GNU make 4.4.1, each probe in a fresh directory, and every edit was built and run green on a clone before this brief was written.

**A recipe after `;` on the rule line.** gmake reads `all: dep ; @echo $<` as a rule whose first recipe line is `@echo $<`. mk takes the `;` for a prerequisite: `mk: *** No rule to make target ';', needed by 'all'.  Stop.`. `all:;@echo x` asks for a target named `;@echo`. The `;` counts only after the rule's `:` and before any `=` or `#`: `X = a ; b` is a value, `t: p # c ; d` is a comment, and `t:;X=1` is a rule (mk took it for an assignment to a variable named `t:;X`). After the `;` the text is recipe text. gmake keeps a `#` there (`all: ; @echo 'a#b' a#b` prints `a#b a#b`), and keeps a `|`, `::` or `%`, which mk refused by name as an order-only prerequisite, a double-colon rule or a pattern rule. It drops the leading whitespace but keeps the trailing whitespace of the line it echoes, and keeps a backslash-newline for the shell (`-n` prints `echo one \` and then `two`). A new `rule_semicolon` in parse.lu finds the `;`. `strip_comment` keeps a `#` after it, and `join_continuations` continues such a line the way it continues a recipe line. `parse_lines` reads only the head before the `;` as the line (the refusals, the assignment, `.PHONY`, a top-level `$(…)`, the rule), then pushes the text after it as the rule's first recipe line.

**The empty recipe.** `t: ;` is a recipe that runs nothing. For a recipe line that expands to nothing (`\t$(EMPTY)`, `; @`), gmake echoes nothing and runs nothing. mk printed an empty line there, serially and under `-n` and `-j`. gmake reports every goal whose update started no command. It says `mk: 'all' is up to date.` for an empty recipe. It says `mk: Nothing to be done for 'all'.` for a target with no recipe, a phony target, or a file with no rule (`mk -f empty.mk empty.mk`, where mk said nothing). A goal named twice gets the same message again; mk said `is up to date` there even for a target with no recipe, and printed it under `-s`. Serially, `Vars.commands_started` counts the recipe lines run (printed, under `-n`), and `build_goals_serial` prints `goal_message` for each goal that started none. `build_recursive`'s two messages and its `is_goal` parameter go. Under `-j`, a `ran` map marks the targets under which a command ran.

**The rule with neither.** With `out: FORCE` and `FORCE:` (no recipe, no prerequisites), gmake remakes `out` every time, and `$?` is `FORCE`. mk said `mk: 'out' is up to date.`. gmake counts a prerequisite that does not exist once its rule has run as newer than its target. mk's `is_out_of_date` and `newer_prereqs` skipped it, and under `-j` a target with no recipe left the targets above it unmade.

/// The index of the `;` that starts the recipe on a rule line (`t: p ; recipe`),
/// or -1. The `;` comes after a `:` and before any `=` or `#`, outside `$(…)` and
/// `${…}`: `X = a ; b` is a value and `t: p # c ; d` a comment.
fn rule_semicolon(line: str) -> int {
    var depth = 0
    var colon = false
    var i = 0
    while i < line.len {
        // a byte inside a multi-byte character is none of these
        let c = line.get(i..i + 1) else ""
        if depth > 0 {
            if c == "(" || c == "{{" {
                depth += 1
            } else if c == ")" || c == "}}" {
                depth -= 1
            }
        } else if c == "$" {
            let next = line.get(i + 1..i + 2) else ""
            if next == "(" || next == "{{" {
                depth = 1
            }
            i += 1
        } else if c == "#" || c == "=" {
            return -1
