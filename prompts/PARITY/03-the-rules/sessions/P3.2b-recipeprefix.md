# P3.2b — `.RECIPEPREFIX` (one session)

Measured at `d77c822` on wolf 0.2.36 against GNU make 4.4.1, each probe in a fresh directory; every edit below was built and run green on a clone first.

**What gmake does.** From the line after `.RECIPEPREFIX = >`, a line that starts with `>` is a recipe line and one that starts with a tab is an ordinary line: `\tX = 1` sets `X`, `\tfoo: ; @echo foo` is a rule, and `all:` then `\t@echo tab` is `under.mk:3: *** missing separator.  Stop.`. Only the first character counts (`>>` is `>`), and an empty value is a tab again. A `#` in a prefix line is recipe text. A continued recipe line drops one `>` and keeps a tab (`-n` prints `echo four \`, `>five \`, `\tsix` for `>echo four \`, `>>five \`, `\tsix`). Outside a rule a prefix line is read as written: `>X = 1` sets the variable `>X`, `>Y = a \` then `>b` is `a >b`, and `>echo x` is `recipe commences before first target`. The value is read unexpanded (`.RECIPEPREFIX = $(P)` makes `$` the prefix). A `.RECIPEPREFIX` in a branch not taken changes nothing; an included file and `$(eval)` text start from the current value. mk read none of it (`>@echo hi` was `missing separator`, and `\t@echo tab` ran).

**The design.** `join_continuations` reads a whole file before `parse_lines` evaluates any of it, while the prefix can change in a conditional, an included file or `$(eval)`. Commit 2 starts it from the current prefix (`recipe_prefix(v)`). It follows the `.RECIPEPREFIX = V` and `:= V` lines outside conditionals and define bodies, returns a prefix line as a tab line and a tab line as an ordinary one (so `parse_lines` reads recipe lines as before), and records each line's prefix in the new `Line.prefix`. `parse_lines` drops a prefix other than a tab from each continued recipe line and reads a prefix line outside a rule as written. Commit 3 refuses by name a line whose recorded prefix is not the variable's, so mk is never silently wrong where it cannot follow: `mk: FILE:N: .RECIPEPREFIX set in a conditional, an included file, $(eval) or from a reference is not supported`. Its two files in `tests/corpus/refuse/` (rows R1, RJ) print `tab` today.

**A tab line outside a rule** that is read as a makefile line (P3.2) is now joined and stripped as one: `\tW = a \` then `\t    b` is `a b`, and `\tZ = 3# c` is `3`. mk kept the backslash-newline and the comment.

/// A physical line as the reader reads it under the recipe prefix `p`: one that
/// starts a logical line with `p` is a tab line, and a tab line that does not
/// start with `p` is an ordinary one. Under a tab, or continued, it is as written.
fn prefixed_line(raw: str, p: str, continued: bool) -> str {
    if p == "\t" || continued {
        return raw
    }
    if raw.starts_with(p) {
        return "\t" + raw[p.len..]
    }
    if raw.starts_with("\t") {
        return raw.trim_start()
    }
    raw
}

/// A recipe-style logical line read as a makefile line: each backslash-newline,
/// with the whitespace around it, is one space, as join_continuations joins one.
fn joined_line(text: str) -> str {
    let parts = text.split("\n")
    var out = parts[0]
    var k = 1
    while k < parts.len {
        out = out[0..out.len - 1].trim_end() + " " + parts[k].trim_start()
        k += 1
    }
    out
}

/// The recipe prefix after the line `w`, read outside conditionals and define
/// bodies: `.RECIPEPREFIX = V` or `:= V` (`override` and `export` too) makes it
/// V's first character. Any other change is the reader's to refuse.
fn prefix_after(w: str, prefix: str) -> str {
    var rest = w
    if rest.starts_with("override ") {
        rest = rest[9..].trim_start()
    }
    if rest.starts_with("export ") {
        rest = rest[7..].trim_start()
    }
    let a = parse_assignment(rest, 0) else {
        return prefix
    }
    if a.name == ".RECIPEPREFIX" && (a.op == "=" || a.op == ":=") {
        return prefix_char(a.value)
    }
    prefix
}

/// A recipe prefix: the first character of `value`, a tab when it is empty.
fn prefix_char(value: str) -> str {
    var n = 1
    while n <= value.len {
        let c = value.get(0..n) else ""
        if c.len > 0 {
            return c
        }
        n += 1
    }
    "\t"
}

/// The recipe prefix `.RECIPEPREFIX` gives now.
fn recipe_prefix(v: Vars) -> str {
